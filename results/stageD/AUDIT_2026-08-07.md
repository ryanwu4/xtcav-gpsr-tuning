# Stage-D fit pipeline — bug audit

12 distinct defects survived adversarial verification (deduplicated from 19 lane reports; the charge-split mismatch was found independently by 4 lanes, the figure-seed default by 4, the orientation-baseline mismatch by 2).

---

## 1. CRITICAL — Missing 1.0334 m back-drift: the flow's XTCAVF-**exit** cloud is injected at the XTCAVF **entrance**

`src/xtcav_gpsr_tuning/fit.py:239` (`forward`), `:291` (`forward_full`), `:332` (`forward_off`)

The surrogate's training data is saved at the XTCAVF element **exit** (`save_beams_at: [XTCAVF]` → `tao.bunch_data`, exit plane; confirmed by Stage-A test `1_pure_optics_exit_to_exit` at rms 4.3e-6). The fit's segment is built with `start_after=None`, so its first element is the full 1.0334498 m XTCAVF crab cavity. `segment.back_drift` — documented as mandatory at fit time in `docs/stageB_runbook.md:123-126` and in the Stage-B analysis note — is never called anywhere in `fit.py` (only in `scripts/validate_segment.py:135` and `scripts/stageA_figures.py:49`). The beam is therefore propagated through one extra TDC length of drift-free optics.

**Concretely wrong:** the spec's own matrices show the omission is exactly one TDC-length drift (`R_exit[3][4] = -4.4349`, `+ R33·1.03345 = -3.0679 = R_entrance[3][4]`, i.e. R34 differs by 45%). Measured on CPU at the production config: σ_y is **25–30% too small at every scan step and both streak signs** (e.g. step 1, sign +: 449 µm rendered vs 627 µm with the back-drift). σ_x moves <3%. This is silent to every sim-to-sim gate because target and model share the same wrong forward. It plausibly manufactured both the `sdelta` nuisance (which was introduced to absorb a σ_y deficit: model 427/390/269 µm vs real 778/774/702 µm — the correction closes roughly half the gap) and part of the Stage-C "irreducible surrogate error" floor (`results/stageC/imagegap.json`, median TV 0.77 against a 0.05–0.09 floor).

**Invalidates:** all four precal JSONs (`register`, `lambda`, `control`, `nuy` — the Jacobian/SVD subspace and λ* are computed on wrong optics), any fresh D3 run, `stageC/imagegap.json`, `bmadrecovery.json`, `gates_final.json`.

**Minimal fix:** in all three forward methods, `beam = back_drift(beam, float(self.s.spec["meta"]["tdc_length_m"]))` between `cloud_to_beam` and `segment.track`. `calibrate_veff` needs no change — it linearizes the segment, not the beam.

## 2. MAJOR — TCAV-off targets are ~20–27% streaked-shot contamination at 18 of 33 steps, entering the loss unweighted and ungated

`src/xtcav_gpsr_tuning/targets_real.py:255-265` (pooling), `src/xtcav_gpsr_tuning/fit.py:476-477`, `:533-534` (unweighted mean)

`build_targets` takes `cls['ix_off']` verbatim with no amplitude gate, phase window, min-shot rule or split-half floor — in deliberate contrast to the on-shot channel. But the upstream classifier (`xtcav.classify_tcav_shots`) defines off as `amp < mean_on_amp - 0.5`; with `mean_on_amp = 22.009` for E300_15673 that cut is `amp < 21.51`, and **348 of the 400 "off" shots have amp 18–21.5, i.e. 82–98% of full TCAV amplitude**.

**Concretely wrong:** at step 26, 12 of the 44 pooled "off" shots are fully streaked (per-shot x-rms 877–2868 µm at TCAV amp 20.5–21.5) against 32 genuine spots at 110–161 µm. Because `anchor_and_crop` normalizes each frame to unit sum before averaging, ~27% of that target's mass is streaked content the V=0 forward can never render. Stored off-target x-rms across steps is bimodal: 117–145 µm (clean, 15 steps) vs 426–1120 µm (contaminated, 18 steps), with n_off = 23–46 in both populations — so it is contamination, not statistics. The off term is an unweighted mean over all 33 (`step_weights` are applied only to the streaked term at `fit.py:471-472`).

**Biases:** fitted `ex`, `sdelta`, `dtr` are set partly by garbage targets; `final_off_loss` is uninterpretable; the pre-registered `w_off ∈ {0, 0.3}` sensitivity reads as a physics sensitivity when it is a contamination-weight sweep. Also poisons the `kernel_compare.json` step-30 "real off" entry. Precal is unaffected (it passes no `targets_off`).

**Minimal fix:** gate `ix_off` on TCAV amplitude (`amp < 1`) before pooling; add a split-half floor + step weights for the off channel; assert on each off target's x second moment; rebuild `targets.npz`.

## 3. MAJOR — Baselines are evaluated in the canonical orientation but reported against the winning-orientation fit; the headline TV reduction is overstated

`scripts/run_stageD_fit.py:137` (hard-coded `orient_targets(real, False, False)`), consumed at `scripts/stageD_figures.py:159-160`, `:191`

`stage_baselines` runs first in the stage list and cannot see `orient.json`, so both the δ=0 null and the nuisance-only baseline are always measured against flip0_swap0 targets, while `stage_orient` (`:163`) and `stage_ensemble` (`:190`) use the winning `(fr, sw)`. Image TV is not invariant under the row flip or the sign swap. Nothing downstream re-evaluates the null in the adopted orientation.

**Concretely wrong (measured, two independent reproductions agreeing to 4 d.p. and validated against the archived JSONs):** δ=0 null image loss at the production 30.5 µm kernel = 1.5205 (flip0_swap0) vs **1.3401 (flip1_swap1)**, n=16384; ordering and gap stable at n=4096, so not KDE noise. At the v1 264 µm kernel: 1.4199 vs **1.1379**. The v1 report's headline "1.419 → 0.885 (−38%)" is therefore really **1.138 → 0.885 = 0.253**, which is **below the pre-registered ≲0.35 systematic threshold — that gate flips from pass to fail**. A fresh v3 run at 30.5 µm would quote ~1.52 → ~0.87 instead of ~1.34 → ~0.87, a 1.4× overstatement.

**Secondary, same root:** `orient_targets` (`:56-62`) swaps images/splits/weights but never swaps `real['floors']`, so `stageD_figures.py:196` plots the wrong sign's split-half floor curve against the swapped-order `per_image_tv`. The two sign rows of `floors_tv` differ by 56% on average. In the "+" panel of `per_step_tv.png`, the null curve, the floor curve and the fit curve currently refer to three different target pairings.

**Not affected:** fitted δ̂/pulls/projections, orientation selection, ensemble, sensitivity, all precal outputs — those are internally orientation-consistent.

**Minimal fix:** run `stage_baselines` after `orient` and store baselines keyed by hypothesis (or have `stageD_figures` recompute the null under `main_hyp`); swap `real["floors"]` inside `orient_targets`.

## 4. MAJOR — `best_restart` uses a different criterion than every downstream consumer, and they disagree by 2.5× in max|pull|

`scripts/run_stageD_fit.py:201-206` vs `scripts/stageD_figures.py:130-131`

`stage_ensemble` selects `best = argmin(loss_history[-1])` — the actual MAP objective, including the λ ridge and the nuisance priors — writes it as `best_restart`, then **strips `loss_history` from the persisted runs** (`:204`). `best_restart` is written once and read nowhere (`grep`: one occurrence in the repo). `stageD_figures` independently re-selects by `final_img_loss` alone, i.e. by data fit with the prior term discarded, which systematically favours restarts carrying a larger prior penalty.

**Concretely wrong:** in the shipped v2 flip1_swap1 ensemble, `best_restart = 5` (max|pull| 1.090, Σpull² = 4.33) while the figures and `numbers.json` report restart 7 (max|pull| **2.742**, Σpull² = **15.30**) — for an image-loss difference of 0.2% (0.87275 vs 0.87084). Reconstructed totals confirm the ensemble's choice (0.994 vs 1.007). Two artifacts from the same run name two different restarts as "the best fit", the recorded one cannot be re-derived (loss_history dropped), and the published point estimate is selected by data fit rather than by the posterior that was minimized — which biases the headline pulls away from zero.

**Also here:** the `final_img_loss < 1.0` convergence filter is an undocumented magic literal that already discards 2/8 and 5/8 restarts, and raises `ValueError: min() arg is an empty sequence` if no restart clears it.

**Minimal fix:** record `best_by_total`, `best_by_img_loss` and the final total loss per run in `ensemble.json`; have `stageD_figures` read the recorded index instead of re-deriving it; make the threshold a config value with a fallback to all runs.

## 5. MAJOR (as a reported number) — Charge-split loss compares a sign-invariant drive-**charge** fraction against a sign-antisymmetric image **+x-intensity** fraction

`src/xtcav_gpsr_tuning/fit.py:262-263`, `:308-309` vs `src/xtcav_gpsr_tuning/targets_real.py:116-126`

The model emits `split = t_d·Q_d/(t_d·Q_d + t_w·Q_w)` from the flow feasibility head; `sign` never enters, and `forward_full` literally returns `torch.stack([split, split])`. Stage C's target (`targets.target_charge_split`) matched this. Stage D redefined the target as `image_zlobe_split` — the +x-side intensity fraction of the anchored image, which mirrors under a streak-sign flip — and the model side was never updated. `screen.charge_split`, which exists for exactly this, has no caller outside tests.

**Concretely wrong:** model split = 0.7568…0.7503, bit-identical for both signs; targets plus = 0.680…0.519, neg = 0.304…0.478, pair sums 1.012 ± 0.029. The model value lies **outside all 66 targets**, so `mean|split − target| = 0.2467` — reproducing the archived `null.split_loss = 0.24672` to 8 digits. The best any sign-invariant constant can do is 0.0924. So `final_split_loss` in `baselines.json` / `ensemble.json` / `sensitivity*.json` is a pinned estimator offset, not a goodness-of-fit, and `loss_history[-1]` (which selects `best_restart`, finding 4) carries a common ~0.0247 offset. The model's own rendered images, scored with the target's estimator, do mirror correctly (sign + [0.336 0.445 0.531] vs sign − [0.656 0.695 0.452]) — confirming the physics is fine and only the emitted scalar is wrong.

**Parameter bias is small — do not overstate it.** Three independent gradient measurements agree: the split term is 0.4–3% of the image-term gradient norm on `delta_raw` and exactly zero on `dtr`, `log_nu_y`, `log_sdelta`, `log_ex`. Converting to an equilibrium MAP displacement against λ*=3e-3 gives **≤0.036σ on any single pull** (worst: S2EL_xOffset), ~4% of the largest reported pull and ~1/12 of the 0.42σ control systematic. The one lane that measured 0.068σ rms did so on an unconverged 40-iteration trajectory. Orientation selection is unaffected (`stage_orient` ranks on `final_img_loss`). Precal is unaffected (its split targets come from the same model, so the term is self-consistent and vanishes at truth).

**Note:** this is already documented as limitation #4 in `results/stageD/15673_v1_264um/REPORT.md:138` with a promised "v2: image-based same-estimator split" — the fix was never implemented and the current code carries it into a fresh run.

**Minimal fix:** inside the sign loop, compute the split from the rendered anchored image with `targets_real.image_zlobe_split`, or from the tracked x-coordinates with `screen.charge_split(x_out, q)`. Until then set `w_charge_split: 0` and do not report `final_split_loss`.

## 6. MINOR — `projection_spread` is computed over all restarts including divergent ones, inflating it up to 244×

`scripts/run_stageD_fit.py:202`

`proj` is built from every element of `runs` with no convergence filter; the only filter in the pipeline is the hard-coded `final_img_loss < 1.0` in `stageD_figures.py:130`, which produces a *separate* field `proj_spread_converged`. Since `np.ptp` is maximally outlier-sensitive, the two artifacts disagree badly whenever any restart diverges — which happened in 3 of the 4 archived hypothesis blocks.

**Concretely:** v1 flip1_swap1 stored `projection_spread = [7.10, 11.73, 49.06, 18.88, 35.64, 28.98]` vs converged-only `[2.89, 0.271, 2.28, 2.61, 14.18, 0.119]` — direction 1 inflated 43×, direction 5 inflated 244×. Anyone reading `ensemble.json` directly concludes every registered direction is unconstrained and the ensemble-spread gate fails; the report happened to quote the converged values, so no published number is wrong today. `projection_median` differs by ≤0.46 (median is robust) — that half of the claim is weak.

**Fix:** apply the same filter in `stage_ensemble`, emit both `projection_spread_all` and `_converged` with the surviving indices and the criterion; make the threshold a config value.

## 7. MINOR — Pre-registered identifiable subspace includes a parameter the fit freezes and omits one it fits

`src/xtcav_gpsr_tuning/identifiability.py:49-53`

`jacobian_svd` hardcodes `'veff(MV)'` into the parameter list regardless of whether it is free. Executed `requires_grad` dump on the actual production models: fit-model `{veff_frac: False, l2_shift_deg: True}`; precal-model `{veff_frac: False, l2_shift_deg: False}`. So V_eff is frozen everywhere in Stage D (`fit_veff` in the config has zero call sites in `src/` or `scripts/`), while `l2_shift_deg` — a genuinely fitted DOF — is outside the identifiability accounting entirely.

**Concretely:** kept directions 5 and 6 carry V_eff weights −0.628 and +0.666 (40–44% of their squared norm) on a coordinate that is identically 0 for every restart, so those two projection medians measure only the residual 56–60% of their direction. `n_kept = 8` is overstated by **at most one** (singular-value interlacing: σ₇(J_reduced) ≥ s₈(J) = 0.0695 > cut 0.05 — the finder's "overstates by two" is wrong), and the reported `projection_spread` is unaffected since the veff coordinate is a constant 0.

**Fix:** build the register from a model constructed exactly like `run_stageD_fit.make_model`, include a parameter only when `p.requires_grad`, and add `l2_shift(deg)` when `l2ref_nuisance` is on.

## 8. MINOR / UNCERTAIN — D0 gate is existence-only and currently re-blesses a λ* calibrated under the quarantined k1-leak

`scripts/run_stageD_fit.py:263-268`

The gate checks only that the precal files exist and reads `lambda_star` with no provenance, hash or code-version check. `results/stageD/15673/precal/{lambda,control,nuy}.json` are byte-identical to the copies under `15673_v2_buggy_dtr/precal/`, and `INVALID.md` blesses only `register.json` + targets. The λ L-curve's 8 sequential fits show the monotone k1 drift of the quarantined bug (Q2FF −0.33% → −2.23%). **Stronger, and missed by the finder:** `lambda.json`'s per-fit `dtr ≈ −0.003` is incompatible with the currently configured `dtr_prior_sigma_frac = 0.005` — under today's prior that would cost 0.44 against an image loss of 0.057, ~8× the data term. λ* was tuned for a model with three free width DOFs and is being applied to one where they are effectively pinned.

**Why uncertain:** within each `(make_truth, one_fit)` pair both models read the same drifted k1, so each L-curve point remains a self-consistent recovery experiment, and the resulting `pull_err_rms` curve is a clean U (0.518/0.427/0.411/0.441) whose minimum coincides with Stage C's independently derived λ*=3e-3. Settling it needs a GPU-scale re-run of `--stage lambda`.

**Fix:** stamp a git rev / hash of `fit.py`+config into each precal JSON and have the gate refuse on mismatch; move `lambda`/`control`/`nuy` into the v2 quarantine and re-run D0.4/D0.2/D0.5 under the fixed code.

## 9. MINOR — Figures re-render the best restart with seed 0 because the restart seed is never persisted

`scripts/stageD_figures.py:135` (`best.get("seed", 0)`); root cause at `scripts/run_stageD_fit.py:100-104` / `src/xtcav_gpsr_tuning/fit.py:510-517`. Same dead default at `scripts/stageD_blur_decomposition.py:67`.

No run record ever gets a `seed` key (verified by enumerating all 32 records in both archived ensembles), so the `.get` fallback is the only branch that ever executes, while `stage_ensemble` fitted restart *s* with `seed=s` — which selects the frozen CRN buffers `zd`/`zw`. The gallery "MAP fit" panel and the derived `numbers.json` entries `separation_rms_um` / `offspot_um` are therefore computed from a particle realization that was never optimized.

**Magnitude is small — three independent measurements agree.** At n=2048–8192, two-lobe separations move 2–25 µm on 740–3830 µm and off-spot σ_y moves 0.4–5.3 µm on ~400 µm; scaled to the production n=65536 that is **~0.1–0.5%**, against fit-vs-null differences of 27–224 µm. The per-step TV overlay, `best_img_loss`, pulls, projections and all JSON outputs are read straight from `ensemble.json` and are unaffected. The real cost is reproducibility: neither the latent seed nor the jitter seed (1000+s) is persisted, so no restart can be re-rendered exactly from its artifact.

**Fix:** `res["seed"] = seed` in `fit_once` (and `r["restart"] = s`), then index it, failing loudly rather than defaulting. Immediate workaround: `seed = h["runs"].index(best)`.

## 10. MINOR — Model images are not renormalized after `com_center_image` while targets are

`src/xtcav_gpsr_tuning/fit.py:259`, `:306`, `:343` vs `src/xtcav_gpsr_tuning/targets_real.py:113`

Cheetah's `kde_histogram_2d` normalizes over the grid, so the pre-anchor model image is unit-sum; `com_center_image` then does a zero-padded `grid_sample`, destroying content pushed off frame, and nothing renormalizes. Targets are exactly unit-sum. Under Stage D's `anchor='none'` the render grid also stays centred on the design orbit rather than the beam COM, so the field of view is asymmetric between model and target.

**Measured scope: 1 of 66 images.** Step 1, sign −, sums to 0.889–0.903 (9.4% of charge outside the grid); step 2, sign − loses 0.7%; the other 64 are exactly 1.0. That is a hard irreducible +0.11 TV on one image = **≤0.0015 on the weighted mean image loss** (0.1% of the quoted 1.52/0.87), identical in null and fit, so the reduction is unaffected. **The claimed bias on `sdelta`/ν_y is refuted by measurement:** sweeping the width nuisances, `sdelta=2.0` *reduces* total missing mass from 0.0975 to 0.0557 and `sdelta=2.5, ex=1.5` gives 0.0833 — there is no coherent shrink pressure.

**Fix:** `img = img / img.sum(dim=(-2,-1), keepdim=True)` after the anchor; better, mirror the target pipeline (oversized grid → COM-centre → centre-crop → renormalize).

# Clean

Six lanes ran adversarial verification with executed CPU reproductions. What was checked and found **sound**:

**Shared state / aliasing (the k1-leak family).** Decisive test: the same fit run (a) alone in a fresh process, (b) after an identical fit, (c) after the full baselines → nuisance-only → 4 orient combos → student_t → veff×1.10 → bandwidth×0.7 sequence in one process gave **bit-identical** results (max |Δpull| = 0). Quads return to pristine at every `ForwardModel` construction; `Segment.track` neither mutates the input beam nor caches a map; `calibrate_veff` rebinds rather than mutates and restores in a `finally`; `copy.copy(setup)` in `stage_sensitivity` is a genuine shallow copy; no duplicate element names for Q2FF/Q1FF/Q0FF/XTCAVF; Cheetah stores voltage/phase/k1 as buffers, so Adam's parameter list is unpolluted. *One remaining landmine, not a defect today:* `scripts/stageD_kernel_compare.py:62` and `stageD_blur_decomposition.py:72` mutate the **shared** `setup.grid` in place — harmless only because both scripts exit immediately.

**Loss algebra and chunked gradients.** `run_fit_chunked` reproduces monolithic `map_loss` to 9e-8 relative on the total and 1e-5–1e-7 relative on every gradient component (residual is float32 reduction-order noise inside the flow). Per-image TV `sum/(2B)`, split `sum/(2B)`, off `sum/W` all correct; the duplicated split across signs is **not** a double count; the L2_ref prior appears exactly once; `_nuisance_prior` is correctly outside the λ scaling; priors added once per iteration; grads accumulate correctly across chunks. The `combined = W == B` branch was verified to give identical losses and gradients to the non-combined path. Adam correctly excludes `requires_grad=False` params; `CosineAnnealingLR` stepping order correct.

**Determinism / CRN.** Repeated `model()` calls bitwise identical; `forward_full()[0] == forward()[0]` exactly, so streaked and off channels genuinely share one flow sample; `torch.Generator().manual_seed()` is a CPU generator so CPU and GPU reruns get identical latents; no global-RNG use anywhere in the fit path. **Truth/fit independence in `run_stageD_precal.py` is respected in all three stages** (lambda 100+seed, control 400+seed *and* a different n_particles, nuy from a dedicated `default_rng`) — the λ calibration is not self-fulfilling. Varying the latent buffer across restarts was measured *not* to corrupt `best_restart` selection (0.0016 TV at n=65536 vs a 0.0188 converged-loss spread). `sample_bunch` raises on shape mismatch rather than silently redrawing. Chunk size does not perturb results.

**Physics / units / conventions.** `scale_bunch` column order matches `norm.json` `coord_keys`; pz-only energy scaling preserves ⟨pz⟩ to 1e-14; (x,px) scaling is about each bunch's own centroid so drive/witness separation and tilt are untouched. `calibrate_veff` verified exactly linear in the probe (7/14/28/56 MV all → 27.482100 MV) with the +0.6 m drift inside the calibrated segment, so the geometry factor appears once. TDC physics self-consistent (`R[2][0] = R36·R[5][0]` to 3 digits). `conditioning()` u=0.5 baselines reproduce the recorded BACTs to <0.002 kG and the energy-offset baselines to <20 keV; the scanVal sign is corroborated by the monotone x-rms trend in both model and data. `load_targets` axis layout, `orient`/`orient_targets` transforms, and `identifiability._images_at` parameter packing all verified consistent.

**Targets / orientation.** Anchor+crop geometry is exactly centred for the even/even case; the row flip commutes with COM anchoring to machine precision (ny=160 even, COM at 79.5); step↔scan-value pairing verified elementwise between `machine_config.json` and `targets.npz`; the split-half floor uses a correct interleaved split with correct σ-of-the-mean scaling; `select_shots`' fallback honestly reports the window it used and is not triggered on this dataset; artifact repair correctly happens in the camera frame before anchoring.

**Config plumbing.** The PyYAML "0.6e6 parses as str" trap is handled at every one of the four consumer sites; every other new numeric key parses correctly; λ is taken from `precal/lambda.json` and the run refuses to start without it; all 25 config keys traced to real consumers with correct spelling.

*Noted, deliberately not filed:* the docstring for `ex` describes a width scale not an emittance scale (ε scales as `exp(2·log_ex)`) — a report-wording risk only; `run_stageD_nuy_residual.py:31` hardcodes `lam = 3e-3` instead of reading `lambda.json` (benign today, will drift); the orientation rule "winner ≥ 2× runner-up" on a TV floored at ~0.12 and saturating near 1.9 is vacuous (observed ratios 1.01 and 1.08, so `carry_both` is always True); a per-step mask would silently mis-broadcast in `run_fit_chunked:468` (inert — the stored mask is all-ones); the split term is unweighted and NaN-unguarded (inert — min n_shots = 5).

# Fix order

### Phase A — before anything is re-run (require the full production chain: precal ~12 h + fit ~14–20 h GPU)

1. **#1 back-drift.** Nothing downstream is meaningful until this lands. It changes R34 by 45% and σ_y by 25–30%, so it invalidates precal *and* fit, and it may make the `sdelta` nuisance unnecessary — re-examine whether to keep it after refitting.
2. **#2 off-target contamination.** Rebuild `targets.npz` with an amplitude gate. Do this in the same pass as #1: it changes the data the fit sees, so it cannot be applied to a run in flight.
3. **#5 charge-split estimator.** Switch the model side to the image-based estimator (or set `w_charge_split: 0`). Changes the objective → refit. The δ̂ impact is ≤0.04σ, but the reported residual is currently meaningless.
4. **#8 precal provenance.** With #1 landed, `lambda`/`control`/`nuy` must be regenerated anyway. Add the provenance stamp + gate now so this class of stale-blessing cannot recur.
5. **#7 register parameter set.** Build the register from the fit's own model (drop frozen `veff`, add `l2_shift`). Part of the precal re-run, so free at this point.

> **A production rerun already in progress is invalidated by #1 and #2 regardless of what else you do.** If one is running now, stop treating its output as publishable; there is no reason to preserve it.

### Phase B — safe to apply immediately; do not invalidate a run in flight, and can be applied to existing artifacts

6. **#4 `best_restart` criterion.** Highest-value item in this phase: it currently swings the headline max|pull| by 2.5×. Record both criteria and the per-run total loss, and have the figures read the recorded index. Post-hoc re-derivation on *existing* artifacts is impossible (`loss_history` was stripped) — but the code fix costs nothing and takes effect on the next run.
7. **#3 orientation-consistent baselines** + swap `floors` in `orient_targets`.
